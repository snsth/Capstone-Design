# 2D 파트 호러 이벤트 타임라인 기획서

> 이 문서는 구현 스펙입니다. 코드는 포함하지 않으며, Claude Code에서 이 문서를 참고해 `HorrorEventManager.cs` 및 관련 스크립트를 수정/구현하는 데 사용합니다.

## 1. 배경 및 목표

- 2D 파트는 게임의 메인 콘텐츠가 아니라 **3D 파트로 넘어가기 전의 인트로/훅(hook)** 역할이다.
- 총 플레이 타임은 **약 120초(2분)**로 고정한다.
- 목표 감정 곡선: **적응 → 몰입 → 의심 → 확신 → 충격 → 전환**
- 단순히 무서운 이벤트를 많이 넣는 것이 아니라, **타이밍과 정적(silence)을 활용해 적은 수의 이벤트로 임팩트를 극대화**하는 것이 핵심.
- 마지막 이벤트(강제 사망)는 3D 씬 전환의 트리거가 되어야 하므로, 게임 시스템(승리 조건 등)과 충돌 없이 반드시 발동되어야 한다.

## 2. 선행 수정 사항 (구현 전 필수 확인)

이 타임라인이 정상 작동하려면 아래 항목이 먼저 정리되어야 한다.

### 2-1. `Gamemanager.cs` — `maxGameTime`
- 현재 기본값이 40초(`4 * 10f`)로 설정되어 있어, 120초 타임라인을 적용하기 전에 승리 처리(`GameVictory()`)가 먼저 발동해버린다.
- `maxGameTime`을 **120초**로 변경해야 한다.

### 2-2. `Spawner.cs` — 난이도 구간 분배
- `levelTime = maxGameTime / spawnData.Length` 구조이므로, `maxGameTime`이 40→120초로 늘어나면 기존 `spawnData` 배열 길이가 그대로일 경우 각 난이도 구간이 비례해서 늘어져 적 강도 상승이 체감상 너무 느려진다.
- `spawnData` 배열의 항목 수를 늘리거나, 120초 기준으로 구간을 재설계해야 한다. (예: 20초 단위로 6단계 정도 권장)

### 2-3. `HorrorEventManager.cs` — 이벤트 발동 조건과 게임 종료 조건의 경합(race condition)
- `HorrorEventManager.Update()`는 `Gamemanager.instance.isLive == false`이면 즉시 리턴하므로, 승리 조건(`gameTime > maxGameTime`)이 먼저 걸려 `isLive = false`가 되면 마지막 이벤트(강제 사망)가 영영 발동하지 않을 수 있다.
- 따라서 강제 사망 이벤트의 발동 시각은 **`maxGameTime`보다 반드시 일정 여유를 두고 앞서야 한다.** (권장: maxGameTime − 2초 이상)

## 3. 전체 타임라인 (120초 기준)

| 시각 | 이벤트명 | 분류 | 목적 |
|---|---|---|---|
| 0~8초 | (없음) | - | 순수 적응 구간. 절대 이벤트를 넣지 않는다. |
| 12초 | 서브리미널 플리커 | 떡밥 | "방금 뭐였지?" — 인지조차 애매한 1차 신호 |
| 25초 | 애매한 스팅어 | 떡밥 | 화면 변화 없이 소리만으로 의심 누적 |
| 40초 | 정적 노이즈 | 확정 이벤트 | 첫 번째로 "확실히 이상하다"고 느끼는 지점 |
| 60초 | 적 전체 동결 | 위화감 | 조용한 정지, 중반 전환점 |
| 75초 | 점프스케어 | 충격 | 타임라인 중 가장 강한 단일 충격 (전체의 약 62%, 정중앙이 아닌 살짝 앞) |
| 90초 | 대규모 스폰 | 압박 | 점프스케어 이후 시각적 혼란으로 분위기 전환 |
| 105초 | 노이즈+동결 콤보 | 고조 | 엔딩 직전 긴장 재고조 |
| 118초 | 강제 사망 → 3D 전환 | 클라이맥스 | 게임 종료 트리거, 끊김 없이 3D로 연결 |

**설계 원칙**
- 평균 이벤트 간격 13~15초 유지 → 늘어지지 않으면서도 플레이어가 다음 이벤트를 예측하지 못하게 한다.
- 점프스케어(가장 강한 비트)를 타임라인 정중앙이 아니라 약간 앞쪽에 배치하여, 마지막 강제 사망의 임팩트가 묻히지 않도록 한다.
- 초반 두 이벤트(12초, 25초)는 게임플레이를 전혀 방해하지 않아야 한다 (입력 차단 금지, 화면 변화는 1프레임 이내).

## 4. 이벤트별 상세 스펙

### 4-1. 서브리미널 플리커 (12초)
- **목적**: 인지했는지 안 했는지 플레이어 스스로도 확신할 수 없는 수준의 미세 신호.
- **시각 연출**: 화면 전체 오버레이를 아주 옅은 톤(거의 안 보이는 수준)으로 **단 1프레임만** 표시 후 즉시 원상복구.
- **청각 연출**: 0.1~0.2초 길이의 매우 짧은 노이즈/클릭음 1회.
- **제약**: 게임 진행, 입력, 적 동작에 어떤 영향도 주지 않는다. 완전히 연출 전용.

### 4-2. 애매한 스팅어 (25초)
- **목적**: 화면엔 아무 변화가 없는데 소리만 한 번 들리게 하여 "방금 그거 진짜였나?" 하는 의심을 키운다.
- **시각 연출**: 없음.
- **청각 연출**: 방향성이 불분명한 저음 웅웅거림 또는 짧은 앰비언트 이상음 1회.
- **제약**: 4-1과 마찬가지로 게임플레이에 영향 없음.

### 4-3. 정적 노이즈 (40초) — 기존 `Event_StaticNoise` 재사용
- 기존 구현 그대로 사용. CRT/전기 노이즈 SFX 재생 + BGM에 하이패스 필터로 음질 왜곡.
- 이 시점부터는 플레이어가 "확실히 뭔가 있다"고 인지해야 한다.

### 4-4. 적 전체 동결 (60초) — 기존 `Event_EnemyFreeze` 재사용
- 기존 구현 그대로 사용 (3초 동결, 화면 살짝 어둡게, BGM 볼륨 다운 후 노이즈와 함께 급격히 재개).

### 4-5. 점프스케어 (75초) — 기존 `Event_Jumpscare` 재사용, 강도 검토
- 기존 구현(빨간 화면 빠른 점멸 3회 + 큰 소리) 유지.
- 이 타임라인에서는 **타임라인 전체 중 가장 강한 단일 비트**이므로, 직전(60초 동결)에서 화면과 소리가 충분히 가라앉아 있어야 대비 효과가 산다. 동결 이벤트의 페이드 아웃이 끝난 직후 곧바로 이어지지 않도록 최소 10초 이상의 평온 구간을 보장한다.

### 4-6. 대규모 스폰 (90초) — 기존 `Event_MassSpawn` 재사용
- 기존 구현 그대로 사용. 점프스케어로 인한 긴장을 시각적 물량 압박으로 전환시키는 역할.

### 4-7. 노이즈+동결 콤보 (105초) — 기존 `Event_NoiseAndFreeze` 재사용
- 기존 구현 그대로 사용 (정적 노이즈 → 동결 → 동결 해제 직후 추가 스폰).
- 엔딩 직전 마지막 긴장 고조 구간 역할.

### 4-8. 강제 사망 (118초) — 기존 `Event_SuddenDeath` 재사용
- 기존 구현 그대로 사용 (큰 소리 → 화면 적색 → 암전 페이드 → 체력 0 처리 → `GameOver()` 호출).
- **주의**: 발동 시각은 `maxGameTime`보다 최소 2초 이상 앞서야 하며, 이 이벤트가 끝나기 전까지 승리 조건이 먼저 발동하지 않도록 보장해야 한다.
- `GameOver()` → `Result` UI 흐름에서 3D 씬으로의 전환 로직이 자연스럽게 이어지도록 추후 연결 지점을 확인할 것.

## 5. 사운드 디자인 가이드

전체적으로 "확신할 수 없는 소리"에서 "명백한 소리"로 점진적으로 이동하는 구조를 따른다.

| 이벤트 | 사운드 성격 | 검색 키워드 예시 |
|---|---|---|
| 서브리미널 플리커 (12초) | 0.1~0.2초, 고주파 클릭/글리치 | subtle glitch sound, subliminal click |
| 애매한 스팅어 (25초) | 방향 불분명한 저음 웅웅거림 1회 | low hum one shot, ambient anomaly sound |
| 정적 노이즈 (40초) | CRT/라디오 잡음 지속음 | horror static, CRT noise |
| 적 동결 (60초) | 정적 + 저음 드론(긴장 빌드업) | horror drone, tension riser, sub-bass rumble |
| 점프스케어 (75초) | 화이트노이즈 버스트 + 금속성 스크리치 | horror stinger, jump scare sting |
| 대규모 스폰 (90초) | 다수의 발소리/포효 레이어 | horde noise, swarm horror sfx |
| 노이즈+동결 콤보 (105초) | 정적 노이즈 + 드론 재사용 | (40초, 60초 항목과 동일 소스 재사용 가능) |
| 강제 사망 (118초) | 강한 임팩트 사운드 + 암전 후 무음 | horror impact hit, sudden silence stinger |

**소스 추천**
- [freesound.org](https://freesound.org) — CC 라이선스 다수, 호러 SFX 풍부 (라이선스별 저자 표기 필요 여부 확인 필요)
- Zapsplat — 무료 가입 시 사용 가능, 호러 카테고리 별도 제공
- Unity Asset Store "Horror SFX Pack" 계열 — 유료지만 라이선스가 명확하고 퀄리티 일정

**원칙**
- 12초, 25초 이벤트는 절대 크게 키우지 않는다. 작고 의심스러운 정도가 최선.
- 40초 이후부터는 명확하고 또렷한 사운드로 전환하여 "이제 진짜 시작됐다"는 인지를 준다.
- 75초 점프스케어 직전에는 가능한 한 완전한 정적(BGM 볼륨 0에 가깝게)을 만들어 대비 효과를 극대화한다.

## 7. 구현 체크리스트

- [ ] `Gamemanager.maxGameTime`을 120초로 변경
- [ ] `Spawner.spawnData` 배열을 120초 기준으로 재설계 (권장 6단계, 20초 간격)
- [ ] `HorrorEventManager`에 12초, 25초 신규 이벤트 코루틴 추가 (서브리미널 플리커, 애매한 스팅어)
- [ ] 기존 6개 이벤트(`Event_StaticNoise` ~ `Event_SuddenDeath`)의 발동 시각을 본 문서 타임라인(40/60/75/90/105/118초)에 맞게 수정
- [ ] `AudioManager.SFX` enum에 신규 사운드 슬롯 추가 (서브리미널 클릭, 앰비언트 이상음 등) 및 `sfxClips` 배열에 클립 매핑
- [ ] 강제 사망(118초) 이벤트와 승리 조건(120초) 간 경합이 발생하지 않는지 플레이 테스트로 확인
- [ ] 75초 점프스케어 직전 최소 10초간 평온 구간이 유지되는지 확인 (60초 동결 종료 ~ 75초 사이)
- [ ] 전체 타임라인을 실제 플레이로 1회 통과하며 체감 페이싱 검증
